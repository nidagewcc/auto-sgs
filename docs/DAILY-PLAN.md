# 一键日常：任务选择、顺序与结果

开发与验证：**Codex**，2026-11-26。

## 使用

先自行登录游戏并进入主城。程序只检查当前画面，不自动启动游戏、登录、重新登录或切换账号；遇到登录、掉线、协议、公告或渠道 SDK 页面会停止，等待人工处理。

长按悬浮球，打开完整面板，选择「日常设置 · 勾选与排序」。完整面板和设置列表均可滚动，横屏时也能操作底部内容。

- 勾选本轮需要的任务，用「上移 / 下移」调整顺序。
- 点击「保存」后生效；「取消」保留原方案。
- 「恢复默认」仅修改草稿，仍需点击保存。
- 返回完整面板后，「一键日常」下面显示已选顺序和最近一次结果。
- 运行期间不允许编辑或保存方案。每轮开始时复制方案，外部修改不会改变正在执行的顺序。

初始默认仍为 **邮件 → 小乔日常**，保留既有行为。小乔会消耗元宝，设置中有明确提示；本次开发的真机验证不会执行它。

其他任务初始不勾选：

| 任务 | 作用与消耗 |
| --- | --- |
| 玩家信息 | 读取昵称、等级、战力、体力、精力、元宝、玉石，不消费 |
| 紧急军情 | 一键挑战，会消耗体力 |
| 主线副本 | 扫荡会消耗体力；**日常编排中不花元宝重置**，次数为 0 则跳过 |

注意：完整面板里独立的「主线副本扫荡」按钮仍沿用既有模块的 `allowReset` 开关；上表的「不重置」是日常执行器传入的本轮限制，不改变独立任务原有设置。日常编排器不会因某步失败自动重跑；小乔任务自身既有的「再次执行」确认逻辑保留。

## 如何判定结果

不再把「函数没有抛异常」当作业务成功。每个已选任务单独记录：

| 状态 | 含义 |
| --- | --- |
| 成功 | 任务返回了可识别的业务完成证据，并确认返回主城 |
| 跳过 | 如明确没有可领取邮件、无可用军情入口、副本次数为 0 且不重置 |
| 待确认 | 操作结束但业务证据不足，不计入成功 |
| 失败 | 任务异常、必要字段无效，或未能安全恢复主城 |
| 未执行 | 初始检查失败、恢复失败或前序任务停止后，没有开始该步 |
| 已停止 | 当前任务执行期间收到停止请求 |

具体证据：邮件需看到奖励或明确空状态，仅点击按钮为待确认；军情需识别全部三关击杀，部分识别为待确认；副本需战报和「总计获得」，仅有战报为待确认；玩家信息需七个字段类型及数值有效；小乔仅见奖励弹窗不再直接断言整套日常完成，要继续看到既有完成标志。

这些证据仍基于现有模板、OCR 和小乔完成标志识别，不能代替游戏服务端账单或奖励流水。此轮未将其扩展为更强的服务器侧验证。

## 页面恢复与停止

每步执行前后，使用连续两帧确认横屏比例、限定区域内的主城锚点（阈值至少 0.85）、体力与精力分数，并排除已知弹窗。不会使用旧主城检测中的全屏低阈值兜底来授权下一步。

失败后只处理与刚执行任务对应的已识别页面：邮件关闭按钮、助手面板/奖励、军情面板、副本战报/次数面板/地图等。每次只退出一个已确认的页面，再重新取图。未知页面停止后续任务，不盲点返回，不确认消费弹窗，不自动重跑。

- 邮件失败后若严格恢复主城，可以继续下一个独立任务。
- 小乔或副本结果失败/待确认时，即使恢复主城也停止本轮剩余任务，避免游戏内部流程尚未结束而交叉执行。
- 后续恢复发现用户切换到其他应用，或无法确定前台应用，停止恢复。
- 包括首次检查在内，均要求前台严格为游戏。完全不调用游戏启动/登录流程；不关闭渠道 SDK 弹窗，不点击公告、协议或重新登录。其他应用中的游戏截图不能授权点击。
- 用户停止后，任务令牌及线程中断共同阻止后续步骤；小乔开启/确认、副本重置/确认/扫荡、军情找图完成后的挑战点击均再检查停止。
- 截图授权按钮只在 `com.android.systemui` 中查找，避免误匹配其他应用中的「共享屏幕」文字。

## 保存位置

手机项目调试目录下新增两个 JSON 文件：

- `/sdcard/Download/autosgs-logs/daily-plan.json`：版本和任务顺序、开关。
- `/sdcard/Download/autosgs-logs/daily-last-result.json`：本轮方案快照、每步状态/说明/耗时、恢复结果和总计。

使用固定路径、规范路径检查及同目录临时文件重命名保存。写入失败保留旧文件；配置损坏会停止执行，不静默恢复为会消耗元宝的默认组合。设置界面会明确提示损坏，展示默认草稿，只有用户点击保存才修复。

这些文件受项目现有 `.nomedia` 目录约定保护，不写入相册或私人照片目录，不参与截图轮转删除。

## 开发验证

专项和既有测试：

```text
node tests/daily.js
node tests/daily-recovery.js
node tests/daily-ui.js
node tests/task-results.js
node tests/permission-dialog.js
node tests/overlays.js
node tests/regression.js
node tests/debugshots.js
node tests/archive-phone-debug.js
node tools/build.js
node --check build/bundle.js
git diff --check
```

本地测试使用内存文件、虚拟图像、虚拟点击与时钟，不连接手机或实际消费。设置交互测试加载真实日常后端，验证勾选、排序、保存、取消、忙碌保护、配置损坏提示、滚动与窗口生命周期。

受控真机验证先备份手机运行脚本并比较已知版本；只临时保存「玩家信息」方案，通过真实 Android View 的点击监听器验证设置交互与持久化，重载后检查顺序和开关，再运行只读日常。测试结束恢复原默认方案，未执行邮件领取、小乔、军情挑战或副本扫荡。证据保存在本机 `_shot/`，不入 Git。

开发控制指令 `daily:settings` 可通过既有文件指令或远程命令入口打开设置；它只打开编辑器，不运行任何任务。`daily:readonly` 使用仅含玩家信息的临时方案执行一次严格日常检查，不修改已保存方案，不执行邮件、小乔、军情或副本；同样要求用户已手动进入主城。

## 本次最终验证结果

- 全部 9 组测试通过：142 项有明确计数的专项/回归断言，加上日常设置离线交互检查；构建、bundle 语法及差异检查通过。
- 在真实 Android 设置窗口中验证默认选项、取消邮件与小乔、选择玩家信息、上移、保存；保存的 JSON 与操作一致。
- 重载后选项和顺序保留；取消不写配置；恢复默认并保存后，仅选邮件与小乔。
- 按用户要求，最终版完全移除任务入口的自动启动/登录兜底。用户手动登录主城后，通过 `daily:readonly` 执行一次：耗时 **9.254 秒**，玩家信息七字段读取成功，执行前后均确认主城，报告为成功 1。
- 该只读方案没有更改已保存的默认方案；未执行邮件领取、小乔、军情挑战或副本扫荡，没有消费元宝/体力，也没有自动切号。
- 最终只保留一个悬浮球，手机运行脚本与本地构建 SHA-256 一致。

设置交互证据、本轮结构化报告、部署前脚本备份均在本机 `_shot/` 保留，不入 Git。
