# 配方工作台 v2：多板块多场景信息架构

- 日期：2026-11-27；基于：`WORKBENCH-DESIGN.md`（v1 单图原型已交付 `workbench/`）。
- 触发：用户试用 v1 后反馈——单图单配方结构不够，需要板块/场景/截图序列的项目化管理。
- 约束不变：纯 HTML+原生 JS、双击可开、零网络、不碰 `src/` 与 bundle、数据存 localStorage。

## 一、信息架构（四级）

1. **板块（section）**：固定三个，顺序锁死——「日常任务」「敦煌密窟」「特殊活动」。顶层 Tab/侧栏切换，当前只在「日常任务」放 mock 数据，另外两个允许空态并可新建场景。
2. **场景（scene）**：隶属于板块，**一个场景 = 一份配方**。可新建、重命名、复制、删除、拖拽排序；每个场景独立保存自己的 steps、elements、截图序列和元信息（id/name/tier/onFail/entry）。
3. **截图序列（frames）**：隶属于场景，按步骤顺序排列的多张截图。支持本地**批量导入**（multi-select file input，读为 dataURL 存 localStorage，注意容量异常要 try/catch 提示）、逐张切换、改名、删除、拖拽/按钮调序。每张帧带序号和可选备注。
4. **单帧工作区**：选中某张帧后，主画布只显示并处理这一张；在该帧上创建的 point/roi/template/text 识别物**归属当前帧**，元素模型增加 `frameId` 字段；步骤引用元素时，下拉只列同场景元素（跨帧引用允许，因为同属一个场景配方，但元素卡片要显示来源帧序号）。

## 二、页面布局调整

- 最左：板块 + 场景两级导航树（板块标题固定，其下场景列表，选中态高亮）
- 中间列：当前场景的截图序列条（缩略图横/竖排，显示序号，可点选、拖序、删除、导入按钮）
- 主区：选中帧的标注画布（保留 v1 的取点/ROI/模板工具、2772×1280 坐标换算、标注回显与编辑）
- 右侧：上下两块——上为该帧识别物列表，下为场景步骤时间线（沿用 v1 六类步骤、A/B 档、启停、模拟运行）
- 顶部：场景级操作——配方 JSON 导入导出、Markdown 交接包、版本快照（快照粒度=整个场景，含其帧与元素）

## 三、数据模型迁移

- localStorage 键改为 `auto-sgs-workbench-v2`，结构：
  ```json
  {
    "version": 2,
    "sections": [
      { "id": "daily", "name": "日常任务", "scenes": [ { "scene 结构见下" } ] },
      { "id": "dunhuang", "name": "敦煌密窟", "scenes": [] },
      { "id": "event", "name": "特殊活动", "scenes": [] }
    ],
    "active": { "sectionId": "daily", "sceneId": "...", "frameId": "..." }
  }
  ```
- scene 结构：`{id, name, tier, entry, onFail, frames:[{id, name, index, dataUrl, note}], elements:[{..., frameId}], steps:[...]}`
- v1 的 localStorage 数据做一次性迁移：包成「日常任务」下名为「精力一键领取（迁移）」的场景，找不到就忽略，不报错。
- 导入 JSON 时按新 schema 校验；删除被引用元素仍要求手工修复并给提示。

## 四、模拟运行与交接

- 模拟运行仍在场景级播放步骤；播放时若步骤元素带 frameId，主画布自动跳到对应帧高亮，强化「步骤对应画面」的感知。
- 交接包导出内容增加：板块/场景名、帧清单（序号+备注）、每步引用元素的来源帧，方便 Bot 团队还原流程。

## 五、默认决策（Chief 已定，用户可调）

1. 场景与配方一对一，不做一场景多配方。
2. 图片只做本地导入，真机直播/连拍留到对接阶段。
3. 不做跨场景公共元素库，元素场景内独立；后续复用痛点出现再设计。

## 六、明确不做

- 不做真 OCR/模板裁剪/网络通信/账号体系；占位行为沿用 v1 并在 README 注明。
- 不改 v1 已验证的步骤类型语义和 A/B 档定义。

## 七、交付与回报

- 直接迭代 `workbench/` 目录；更新 README 数据模型与操作说明；`node --check workbench/app.js` 必须过。
- 四件套回报：新增/改动文件、自测的交互清单（重点：三级导航、批量导入、帧归属、迁移、快照）、浏览器实测受限项、已知问题。
- 用户会亲自上手逐项点测，代码里避免依赖浏览器自动化才能验证的写法。
