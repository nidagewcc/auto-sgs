# 配方工作台 v3：中文化、画布缩放与场景分支

- 日期：2026-11-27；基于 v2（板块→场景→帧→标注四级结构已上线）。
- 来源：用户实测反馈四条（UI 粗糙、场景属性缺失、画布不能缩放、识别物卡片英文堆砌）。
- 约束不变：纯 HTML+原生 JS、双击可开、零网络、不碰 `src/`；localStorage 数据从 v2 平滑迁移，不丢已建场景。

## 一、场景属性与状态分支（反馈 1）

### 1.1 场景新增属性
- `schedule` 执行频率：单选「每天一次」/「可重复执行」，场景卡片和编辑器顶部都显示中文标签。
- `branches` 状态分支：一个场景可定义多条分支，每条分支含：
  - 分支中文名（如「在矿中-领收益」「被清出-重新迁矿」）
  - 进入条件：引用一个本场景的识别物（文字/模板/取点），语义先做占位（原型只记录「当某识别物出现时走此分支」，不做真实判定）
  - 该分支自己的步骤序列（复用现有六类步骤）
- UI：场景编辑区增加「分支」折叠区，可增删分支、切换编辑哪条；保留现有线性 steps 作为「默认流程」。模拟运行时可选择分支播放。
- 数据结构向后兼容：无 branches 的旧场景默认只有一条默认流程。

### 1.2 二级菜单交互美化
- 板块/场景导航重做视觉：板块为分组标题（带图标位和场景计数），场景为卡片列表，选中态、hover、排序按钮统一风格；新建场景用弹窗表单（名称+频率+所属板块）替代 prompt。
- 顶部增加面包屑：`板块 / 场景名 / 第 N 帧 帧名`，任何时候都知道自己在哪。

## 二、截图序列归属与交互（反馈 2）

- 帧列表标题固定显示「当前场景：{场景名} 的截图序列（共 N 张）」，切换场景时整列清空重绘，加过渡高亮，杜绝跨场景内容混在一起的观感。
- 帧卡片：缩略图 + 序号 + 中文名 + 备注预览；选中态明显；空场景给引导插画/文案（先导入第一张截图）。
- 批量导入后自动选中新帧并 toast「已导入 N 张到 {场景名}」。
- 拖拽排序保留，同时支持按钮排序；删除确认文案写明会连带删除该帧的识别物。

## 三、画布平移与缩放（反馈 3）

- 滚轮缩放：以鼠标位置为中心，0.25×–4× 范围，显示当前比例；加「适应窗口」「100%」「复位」三个按钮。
- 平移：按住空格拖画布，或鼠标中键拖；触摸板双指平移能兼容更好（做基础支持即可）。
- 标注坐标一律仍存 2772×1280 逻辑坐标，缩放/平移只改视图变换（ctx.setTransform），不污染数据。
- 缩放状态下取点/拖框精度要准：鼠标坐标先经逆变换再换算逻辑坐标，补一组自测（check-v3 里用模拟事件验证缩放后坐标准确性）。

## 四、识别物卡片中文化与表单重做（反馈 4，重点）

### 4.1 命名机制
- 用户全程只见中文名：新建识别物时弹输入框要求填**中文名称**（如「精力图标」「领取成功文字」），内部 `ref` 仍自动生成英文短 ID（现有生成器保留），新增 `label` 字段存中文。
- 界面所有下拉、卡片、画布标注、交接包一律显示 label；英文 ref 只出现在导出 JSON 的机器字段里，并附 `label`。
- 重命名只改 label，ref 不动，引用关系不断。

### 4.2 卡片按识别方式中文分类
- 四种类型中文标题：`取点` / `识别区域(ROI)` / `参考图(模板)` / `文字识别(OCR)`，卡片用不同颜色/图标区分，画布标注同色。
- 坐标合并为一个表单项：ROI/模板显示 `X1,Y1,X2,Y2` 四个数字输入框横排一组，标题「区域坐标」；取点显示 `X,Y` 一组，标题「点坐标」。
- 文字识别(OCR)卡片主流程化：`中文名称` + `识别区域(ROI)` + `期望文字`（必填，即用户说的「我期望看到什么字」，用于后续引擎对比）；把现有藏在步骤里的关键词提到元素层，waitText 步骤直接引用该 OCR 元素，不再重复填字。
- 模板卡片：中文名 + 区域 + 阈值（中文标签「匹配阈值 0–1」）+ 文件名占位说明。
- 自动生成的英文 ID 不再出现在卡片正面。

## 四点五、自然语言说明区（反馈 5，新增）

### 概念澄清（写进 README 和界面引导文案）
- 场景=一个完整的活儿（如领精力、矿战反赶），是容器；配方=干这个活儿的操作说明书（步骤+识别物+分支），从属于场景。
- 界面用中文说人话，不向用户暴露「配方」这种术语：导航叫「场景」，步骤区叫「操作流程」，JSON 区叫「机器配置（高级）」默认折叠。

### 4.5.1 场景说明文本框
- 每个场景顶部增加「流程说明（大白话）」多行文本，字段 `description`，随场景持久化、进交接包、进导出 JSON。
- 用途：用户先口述完整意图和大致步骤（含分支想法），作为结构化步骤的来源与验收标准；Bot 团队后续可据此把自然语言翻译/校对成机器步骤。
- 原型不做 AI 自动翻译（无网络），但预留按钮位「生成步骤（待对接）」置灰。

### 4.5.2 双栏对照
- 场景编辑主区改为左右对照：左栏「流程说明」可编辑长文本；右栏「操作流程」即现有步骤/分支时间线。
- 步骤卡片支持填写一句话「这一步在干嘛」（`note` 字段，中文），模拟运行和交接包都显示，让步骤不再只是英文 type+坐标。
- 交接包 Markdown 顺序调整为：场景元信息 → 流程说明原文 → 分支与操作流程（含中文 note、来源帧）→ 识别物清单 → 机器 JSON。

## 五、视觉与通用交互

- 整体做一轮 UI 整理：统一深色配色、间距、圆角、按钮层级；中文标签替换所有英文术语（tier 显示「A档·资源相关 / B档·日常白嫖」并带说明 tooltip；onFail 显示「失败：跳过记录 / 中止」）。
- 危险操作（删场景/删帧/恢复快照）统一确认弹窗，说明连带影响。
- localStorage 容量异常、图片导入失败给出中文错误提示。

## 六、数据迁移与验收

- schema 升 v3：v2 数据补 `schedule`（默认「可重复执行」）、`branches:[]`、`description:""`、步骤补 `note:""`、元素补 `label`（无中文名时先用 ref 兜底显示，提示用户补中文名）。
- 扩展 `workbench/check-v2.js` 为 check-v3（或新增）：模拟 DOM 验证迁移、label/ref 分离、缩放逆变换坐标、分支增删、OCR 元素结构；`node --check workbench/app.js` 必须过。
- 更新 README：中文操作手册风格，含 v3 新功能说明和数据结构。
- 四件套回报，明确列出无法在 Node 环境自测、需用户浏览器点测的交互（滚轮缩放、拖拽、弹窗）。
