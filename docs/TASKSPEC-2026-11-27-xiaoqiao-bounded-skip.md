# 小乔「无反馈跳过」策略 spec（2026-11-27）

- 派发：**Chief**；承接：码工（terra，纯本地）→ 探针（部署验收）。
- 基线：`main` HEAD `35459c9`。
- 背景变更（用户 2026-11-27 确认）：游戏官方调整小乔日常规则，**不再允许随意重复执行**。点「开启」后若无新任务，游戏只闪 1–2 秒提示条（实测文案「勾选的功能已全部执行完成」，黄字深棕条 bbox `(950,465)–(1822,603)`；另见右侧「托管已开启」类气泡），无模态确认框。
- 用户决策（原话要点）：**不追逐一闪而过的文字、不死磕**。点击后画面没反应，等一段时间 X 掉就行，继续执行其他任务。
- 依据：`docs/DAILY-RUN-XUEYU-2026-11-27.md`、`docs/PROBE-XIAOQIAO-AGAIN-DIALOG-2026-11-27.md`（实测事实保留作背景，其第四节旧规格已标注被本 spec 取代）。

## 设计原则：最小改动，不新增瞬态文字识别

用户明确否定了「追瞬态文字」路线，因此本 spec **不新增** OCR 文案模式、不新增识别区域、不调整 `POLL_MS`。探针实测的横条文字/bbox 仅作背景存档，不写进生产代码。真实完成时游戏会展示**持续存在**的奖励弹窗或绿色完成条（昨日 26 秒成功路径已验证 8 秒轮询足以捕获），现有 `_findReward`/`_done` 判据保持不变。

## 现状问题

`src/tasks/xiaoqiao.js` 的 `run()` 点「开启」后进入 `RUN_TIMEOUT=420000ms` 单循环，无信号时干等 7 分钟超时抛错 failed（今日血域魔神实测），浪费且无信息量。

## 修改要求（只改 `src/tasks/xiaoqiao.js`）

1. **新增常量** `IDLE_WAIT_MS = 60000`：点「开启」后等待**首个正向信号**的有界时间。
2. **两阶段等待**：
   - 阶段一（60 秒）：沿用现有循环体（`_findReward` / `_done` / 「再次执行」兼容分支，`POLL_MS=8000` 不变）。60 秒内出现任一正向信号 → 进入阶段二，行为与现状完全一致，`RUN_TIMEOUT` 仍是真实执行的总上限。
   - 阶段一 60 秒耗尽仍无任何信号：记日志 `sgs.log.i("小乔 60 秒无执行信号，按无任务跳过")`，**不再继续等满 420 秒**，进入跳过收尾。
3. **跳过收尾**：复用现有 `_closeResult()` 的面板关闭与严格主城复检逻辑（金色 X → isHome 复检），**禁止盲点左上角、禁止固定坐标兜底**。
4. **跳过返回值**：`{ status: "skipped", message: "开启后 60 秒无执行信号，按官方新规则判定今日已完成并跳过" }`。确认 daily 编排器（`src/daily.js`）对 skipped 的接线：不中止后续任务、计数归入 skipped 而非 failed。
5. **保留不变**：奖励弹窗、绿条完成、「再次执行」确认（官方若回归仍兼容，本次未观测到也不删）、取消检查 `check()` 每轮生效、消费授权与玉璧/充值红线。
6. **异常不伪装**：面板打不开、按钮找不到、回城失败等真异常维持 throw failed；只有「点开启后安静无信号」这一条路径走 skipped。

## 测试要求（扩展 `tests/task-results.js` 与 `tests/daily.js`，虚拟时钟）

- 点开启后 60 秒无任何信号 → skipped，且断言调用了面板关闭与主城复检；
- 60 秒内出现绿条/奖励 → 走原 success 路径，阶段二行为与现状一致；
- 「再次执行」分支被触发时行为不变（保留兼容）；
- skipped 后 daily 编排继续后续任务，最终计数含 skipped、不含 failed、不中止；
- 面板关闭失败/回城失败仍 throw，不允许假 skipped；
- 断言锁定 `IDLE_WAIT_MS=60000` 与 `POLL_MS=8000` 未被改动，防回退、防夹带。
