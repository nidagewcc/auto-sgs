# 配方工作台 v5：场景管理简化

- 日期：2026-11-27；基于 v4（画布优先布局已成型）。
- 来源：用户反馈——场景侧不用那么复杂，导航与维护分离，减少侧栏按钮堆叠。
- 约束不变：纯 HTML/原生 JS、双击可开、零网络、不碰 `src/`；v4 数据平滑迁移。

## 一、信息架构调整

### 1.1 顶部三个主 Tab
- 顶部导航固定三个页签：**日常任务 / 敦煌密窟 / 特殊活动**，切换 Tab 即切换板块，替代现在侧栏里的三个分组。
- 当前 Tab 下只显示该板块的场景列表；面包屑相应简化为 `场景名 / 第 N 帧 帧名`。

### 1.2 侧栏只留场景列表（本板块内）
- 去掉每个场景卡片上的 ↑↓重命名/复制/删除 一排按钮和每个分组的「＋场景」重复入口。
- 侧栏顶部放一个主按钮「＋ 新建场景」。
- 场景卡片精简为单行：名称 + 频率小标签；hover 或选中后右侧出现「⋯ 更多」菜单，菜单内含：编辑、复制、删除。
- 截图序列区维持现状（折叠/48px 窄条能力保留）。

### 1.3 场景维护统一进弹窗表单
- 新建、编辑都用同一个 `dialog` 表单，字段：
  - 场景名称（必填中文）
  - 所属板块（新建时可选，编辑时只读或允许改并迁移数据）
  - 执行频率：每天一次 / 可重复执行（单选）
  - 排序权重：数字输入，默认按创建顺序给递增值（如 10、20、30，便于插队）
  - 入口描述、失败策略、流程说明（说明文本较大，可放弹窗内 textarea 或保留在右栏流程 Tab，二选一，建议说明仍留右栏编辑，弹窗只放元信息）
- 删除走危险确认弹窗，写明会连带删除帧/识别物/步骤。
- 复制场景弹出命名确认，默认「原名（副本）」。

### 1.4 排序改字段驱动
- 场景模型增加 `order`（数字权重，升序排列，值越小越靠前）。
- 列表按 `order` 排序，不再使用拖拽和 ↑↓ 按钮；弹窗里改权重即调整顺序。
- v4 迁移：现有场景按当前数组顺序补 order=10,20,30…。
- check 脚本补：迁移后 order 唯一递增、改 order 后列表顺序变化。

## 一点五、截图序列独立成列与维护简化（用户追加）

### 1.5.1 布局回调
- 画布不再独占弹性大栏：主区改为「截图序列列 + 画布列」两栏，截图序列固定独立一列（建议 180–220px，可折叠成窄条），保证任何时候都能看到整组缩略图，不必展开侧栏 details。
- 整体四栏：顶部 Tab 下为「场景列 | 截图序列列 | 画布 | 右栏 Tab」；画布宽度回到舒适工作尺寸，标注时仍可缩放，但默认不撑满。
- v4 的侧栏 48px 折叠窄条能力保留，折叠的是场景+序列整列还是分别折叠，以实现简洁为准，README 说明。

### 1.5.2 截图维护与场景同构
- 帧卡片默认单行：序号+缩略图+中文名，hover/选中出「⋯ 更多」菜单，内含：编辑（改名/备注）、复制、删除、上移、下移（按钮仅菜单内，不常驻一排）。
- 新建/导入统一：批量导入走列顶部一个上传按钮；单张信息编辑用弹窗表单（名称、备注），与场景维护弹窗同一套交互语言。
- 帧排序同样引入 `order` 权重（或在帧弹窗里提供上移下移，二选一，倾向与场景一致用 order：导入时按 10/20/30 递增，弹窗可改数字）；拖拽排序可保留为快捷方式，但不再是唯一手段。
- 删除确认文案写明连带删除该帧识别物与步骤引用。
- check 补断言：帧 order 排序、弹窗菜单操作后数据正确、删除帧后引用提示。
