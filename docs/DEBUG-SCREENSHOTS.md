## 新截图

使用 [截图管理模块](../src/debugshots.js) 的 `sgs.debugShots.save(image, tag)`。默认最多保留最近 20 张，名称为 `dbg_13位时间戳_序号_标签.png`。标签会清洗，不能通过 `shot:../../...` 将图片写到其他目录。

轮转只检查本目录第一层、匹配本程序命名且规范路径符合预期的普通文件。不递归，不跟随文件/目录符号链接，未知命名文件一律保留。保存和轮转共用锁，异常路径释放锁。

`shot:名字`、`tap:x,y` 和截图归一化诊断统一使用新模块。手工 ADB 或旧版探针产生的其他命名图片不属于自动轮转范围；不要继续往相册或 Download 根目录保存调试图。

新代码需要运行后才会执行保存和轮转；仅将 bundle 推到手机不会自动替换内存里的旧引擎。手工创建的 `.nomedia` 则无需等待脚本启动。

## 历史截图备份与清理

使用 [受限清理工具](../tools/archive-phone-debug.js)，显式指定授权手机序列号：

```powershell
node tools/archive-phone-debug.js --archive --serial 授权设备序列号
```

工具只枚举固定项目调试目录的第一层，仅匹配已知历史截图命名。备份保存在本机 `_shot/debug-archive-时间/`，生成 `manifest.json`，记录原始路径、大小、SHA-256、尺寸及处理状态。

审阅清单后：

```powershell
node tools/archive-phone-debug.js --clean --serial 同一设备序列号 --manifest 本机备份清单路径
```

清理前验证所有候选：目录真实路径、普通文件、无符号链接、备份目录边界、备份哈希、设备哈希及设备截图尺寸/图片格式。拒绝变化或异常文件。删除前再核对一次，然后在同一次设备命令内检查固定物理路径、文件类型和哈希，只删除那个绝对路径的文件，并确认文件不再存在。没有递归删除、通配符删除或媒体库批量删除。

名字或格式不能确认的文件应设为不清理并说明原因；不要扩大命名规则或目录范围来追求“全部清空”。如果清理中断，清单会记录已完成项，可先核对再继续。文件系统的并发替换无法靠多次路径检查完全消除，因此执行清理期间不要并行向该目录投递截图或让其他程序修改这些文件。
