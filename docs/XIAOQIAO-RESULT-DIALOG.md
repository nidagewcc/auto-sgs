# 小乔结果弹窗关闭修复

整理：**Codex**，2026-11-26。

## 真机现象

切换账号后执行保存的「邮件 → 小乔日常」：

1. 邮件成功，识别奖励并返回主城。
2. 小乔模块识别到绿色「执行完成」条，也调用了关闭流程并记录已回城。
3. 严格日常恢复器复检失败，整轮记录为成功 1、失败 1。
4. 真机截图显示画面中央仍有「军团一键援助」结果弹窗，列出点赞、求援、援助三项的执行结果，底部绿色条同时存在。

原因是旧逻辑把绿色条本身当作最终完成信号；它不能证明结果弹窗已经关闭。若直接宣告成功，会在弹窗仍遮挡游戏时结束并误导用户。

## 修复

位置：[`src/tasks/xiaoqiao.js`](../src/tasks/xiaoqiao.js)。

- 新增结果弹窗标题区域 `RESULT_TITLE_REGION` 和标题候选：`军团一键援助`、`执行结果`、`日常结果`。
- `_resultDialogOpen()` 只在限定区域匹配明确标题，不做全屏模糊判断。
- `_closeResult()` 关闭绿色条时，同时检查结果弹窗；只有标题和绿色条都消失，才允许进入助手面板关闭阶段。
- 标题弹窗三次后仍未关闭则抛出错误，不返回成功。
- 轮询中看到绿色条后，若关闭状态无法确认，返回待确认或失败，不再仅凭绿色条宣告成功。

位置：[`src/daily-recovery.js`](../src/daily-recovery.js)。

- 增加第二道防线：只有上一任务明确是 `xiaoqiao`，且限定区域识别到上述结果标题，才允许点击小乔结果窗口自己的关闭 X。
- 其他任务上下文看到同样文字不会触发点击；未知页面仍返回失败并等待人工处理，不盲点返回。

## 验证

新增/更新测试：

- 绿色条与「军团一键援助」弹窗同时存在时，先关弹窗再回主城，结果成功。
- 弹窗点击后仍不消失时任务失败，不能误报成功。
- 恢复器只在 `lastTaskId === "xiaoqiao"` 时处理该标题；邮件等其他上下文不授权点击。
- 原有奖励弹窗、再次执行、取消和消费点击保护继续通过。

`tests/task-results.js` 增加到 32 项，`tests/daily-recovery.js` 增加到 34 项；全套回归、构建和 bundle 语法检查通过。

## 操作边界

本次发现弹窗后，修复版只部署脚本，没有由代理点击游戏弹窗或切换前台。按照新约定，账号切换、游戏回前台和人工处理弹窗均由用户完成；脚本只在确认主城和明确页面后执行。
