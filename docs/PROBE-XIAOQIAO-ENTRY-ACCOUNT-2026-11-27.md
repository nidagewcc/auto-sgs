## 2. 关键发现：fallback 模板的本质

像素级并排对照（`_shot/cmp-xiaoqiao-entry-strip.png`，模板与四帧等大裁剪叠放）显示：
**`res/img/xiaoqiao/xiaoqiao_entry.png`（33×107）内容是小乔脸部局部（眼睛/脸颊/头发），不是圆木框助手图标。**

这解释了全部现象：
- 黄天当道账号主城阵容含小乔武将，左边缘展示角色的脸与该模板高度相似 → 0.95 HIT；昨天同账号 0.92 HIT 后点击 (48,491) 任务真实成功（26 秒完成+回城），说明该点击位在这个账号功能上有效
- 产品经理账号边缘展示的是其他武将（产品经理/童渊构图），脸不同 → 0.83/0.76，换深色皮肤再降到 0.76
- 即 fallback 高分的真实条件是「左边缘展示角色恰好是小乔脸」，并非「助手悬浮头像存在」的强证明。这是模板鲁棒性隐患，建议后续 spec 评估用圆木框图标重做模板

## 3. 因果判定（回答 Chief 第 4 点）

**差异来自账号自身的展示角色/悬浮控件布局（账号 UI 状态），不是背景皮肤颜色。**

> **后续修正（同日，见 `PROBE-NEWACCT-ENTRY-2026-11-27.md`）**：本节早期把左缘命中物推断为「展示武将脸」。后续对血域魔神与黄天当道两个账号命中位做 tile 像素比对，相似度 0.996、高倍特写为同一张小乔圆图标，而两账号中央展示武将完全不同——证明左缘 (35,488) 是**跨账号一致的独立助手控件**，不是随阵容变的展示武将。产品经理账号该位置相似度仅 0.83/0.76，结论修正为「该账号助手控件未显示（收起/挪位）」。上文第 2 节关于 fallback 模板本身是脸部特写、阈值安全带薄的观察仍然成立。

依据：
1. 产品经理账号内部换肤（浅→深），fallback 仅 0.8309→0.7564，同处不达标带，无质变
2. 同设备同脚本切回黄天当道，同位置立即 0.9517 HIT
3. 三帧最佳匹配点都在 (2,436) 附近、坐标几乎不变，变的是该坐标上的像素内容（哪名武将的脸）
4. 右侧带在所有账号均无助手入口，本项目黑色「三」字悬浮球与游戏菜单是右侧仅有的悬浮元素
- 结论：排除背景因素，锁定账号 UI 状态。产品经理账号的小乔助手入口要么未显示/被收起，要么在其他菜单，静态截图无法进一步定位

## 4. 现状与建议

- 黄天当道账号：小乔链路功能可用（fallback 命中位有昨天成功实证），可继续承载日常
- 产品经理账号：维持安全拒绝，禁止降阈值或全屏匹配（fallback 在无入口时也有 0.76–0.83，降阈值必然误点武将脸）
- 待用户手动排查产品经理账号：左右边缘收起箭头、「福利/任务/更多」菜单内是否有小乔助手，找到后截图发群，探针再定补模板/改搜索带
- 模板重做建议（另开 spec）：以真实圆木框助手图标为模板，替代脸部局部 fallback，从根本上解除「靠武将脸匹配」的耦合
