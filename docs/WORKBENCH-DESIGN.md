# 配方工作台（Workbench）设计稿需求

- 日期：2026-11-27；决策人：用户；落地：码工（纯本地 HTML 原型，不连手机、不改 `src/` 生产代码）。
- 目标：验证「用户编排步骤、机器执行配方」的工作流，先做**纯前端静态原型**，数据用内置 mock，浏览器直接打开即可演示。
- 背景痛点：现有模式每个功能从零量坐标、写状态机，慢且重；需要把「坐标/模板/文字/步骤」变成可热改的数据配方，用户（5 年游戏经验、Java 后端背景）当编排者。

## 一、交付物

- 目录建议：`workbench/`（与 `src/`、`tools/` 平级，独立静态站点，不参与 `tools/build.js` 打包）
- 技术：单页 HTML + 原生 JS/CSS 即可，**不引构建工具、不引框架**（用户机器环境简单，双击能开是硬要求）；如确需库，优先 CDN 单文件并在文档说明
- 数据：内置 1–2 份 mock 截图（可先放占位图或从 `_shot/` 拷一张脱敏主城图）和一份 mock 配方，全部存内存 + localStorage，不发任何网络请求
- 验收：`node --check` 不适用时至少保证 HTML 无脚本错误；在浏览器完整走通下文所有交互；写 `workbench/README.md` 说明打开方式和后续真机对接预留接口

## 二、页面布局（三区）

1. **左栏·画面与标注区（主区）**
   - 显示截图（画布坐标系固定按游戏逻辑分辨率 **2772×1280** 建模，CSS 缩放显示，鼠标位置实时换算回逻辑坐标）
   - 三种标注工具，切换使用：
     - 取点：单击 → 生成点击坐标 `{x,y}`
     - 框选 ROI：拖拽矩形 → 生成 `[x1,y1,x2,y2]`
     - 模板裁剪：在图上拖框 → 生成模板引用（原型阶段只记录矩形和文件名占位，不做真裁剪）
   - 标注结果高亮回显，可命名、可删除、可微调数字
   - 框选区域提供「OCR 占位」按钮（原型只弹假文字结果，接口预留）

2. **中栏·步骤编排区（配方时间线）**
   - 步骤类型（先做这 6 种）：
     - `tap` 点击（坐标或模板定位二选一）
     - `waitImage` 等模板出现（带超时、阈值字段）
     - `waitText` 等文字出现（带区域、关键词）
     - `waitMs` 固定等待
     - `swipe` 滑动（起点/终点/时长）
     - `snapshot` 存证截图
   - 每步可编辑参数、上移下移、复制、禁用、删除
   - 步骤支持标记 **A 档/B 档**（A=资源/钱相关，强制识别确认；B=白嫖类，允许坐标+轻校验、失败跳过）
   - 顶部有「模拟运行」按钮：按步骤逐条高亮播放，用 `waitMs` 真等待模拟节奏，不接真机，让用户直观感受执行流

3. **右栏·识别物库与配方 JSON**
   - 识别物列表：坐标点、ROI、模板、文字关键词，统一命名管理，可被步骤引用
   - 实时生成配方 JSON（只读预览 + 编辑模式），结构见下；支持导出 `.json` 文件、导入回填
   - 「导出交接包」按钮（原型打包为一个文本块/下载文件）：配方 JSON + 标注清单 + 自动生成的 markdown 步骤说明，模拟以后丢给 Bot 团队的交接物

## 三、配方 JSON 草案（原型先定结构，后续真机引擎按此消费）

```json
{
  "version": 1,
  "id": "energy-claim",
  "name": "精力一键领取",
  "tier": "B",
  "entry": { "from": "home", "desc": "主城起始" },
  "steps": [
    { "id": "s1", "type": "tap", "target": { "kind": "image", "ref": "tpl_energy_icon" }, "tier": "B" },
    { "id": "s2", "type": "waitImage", "ref": "tpl_claim_panel", "timeoutMs": 8000 },
    { "id": "s3", "type": "tap", "target": { "kind": "point", "x": 2221, "y": 1106 } },
    { "id": "s4", "type": "waitText", "text": "领取成功", "region": [900, 440, 1880, 630], "timeoutMs": 5000, "optional": true },
    { "id": "s5", "type": "snapshot", "tag": "energy_done" }
  ],
  "onFail": "skipAndLog",
  "elements": [
    { "ref": "tpl_energy_icon", "kind": "template", "rect": [10, 460, 80, 540], "threshold": 0.85 },
    { "ref": "tpl_claim_panel", "kind": "template", "rect": [400, 200, 2400, 1100], "threshold": 0.8 }
  ]
}
```

要求：结构字段命名稳定、注释写在 README；`optional`、`onFail`、`tier` 的语义在界面有说明，不要让用户看代码才懂。

## 四、热修改演示（重点体验项）

- 修改任意坐标/阈值/文字后，JSON 实时变化，localStorage 自动保存，刷新不丢
- 提供「版本快照」按钮：保存当前版本并可回看 diff（原型用深拷贝实现即可），让用户感受以后「改数字不重新构建」的工作流

## 五、明确不做（范围控制）

- 不连手机、不做 WebSocket/HTTP 真机通道、不做真 OCR/模板匹配
- 不改 `src/`、不碰 bundle、不写 AutoJs6 代码
- 不做账号/权限体系；不做多项目管理（单配方演示足够）

## 六、完成后回报

四件套：交付文件清单、浏览器打开方式、每种交互的自测结果、已知限制与真机对接时需要补的接口清单。用户看完原型提修改意见，迭代到满意后再讨论手机端对接，不提前写对接代码。
