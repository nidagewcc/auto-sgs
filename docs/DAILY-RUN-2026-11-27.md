## 3. 邮件 unconfirmed 根因（探针分析，不改代码）

调试图 `_shot/daily-20261127-mail-unconfirmed.png` 显示：邮件窗内实有 4 封邮件（师父保护奖励/军团工资 11.27、竞技场每日奖励 11.26、跨服分红），右侧「师父保护奖励」**附件区显示物品图标 + 绿色对勾 + 数量 132**，即领取动作已生效，证据机制却无法确认。三个识别缺口：

1. **领取成功形态未被 reward 证据覆盖**：代码只认「恭喜获得」浮层文字或 REWARD 模板图（bundle L1035-1038），本次全部领取后游戏在邮件窗内以「附件绿色对勾」呈现，未弹浮层，reward 不命中。
2. **空态文案变体缺失**：OCR 多帧读到「没有邮件啦~」（列表滚到底的空态提示），但 EMPTY_PATTERNS（L1027）只有「暂无邮件/没有可领取的附件/…/无可领取」，不含「没有邮件啦」，empty 也不命中。两边都不命中，5 秒轮询超时即 unconfirmed——这是保守不误判的设计行为，不是任务失败。
3. **状态条文字污染邮件 OCR**：OCR 原文混入「投递-daily·14秒/15秒/16秒」等本项目状态条字样（被引擎误读成「投诺-aily.14秒」等）。EMPTY_REGIONS 第二块 `[700,900,2100,1160]` 与底部状态条区域重叠，本次未造成误判但属隐患。

建议（供 Chief 另派 spec）：EMPTY_PATTERNS 增补「没有邮件啦」类变体；增加附件绿色对勾/已领形态识别；评估邮件 OCR 区域与状态条的避让。
