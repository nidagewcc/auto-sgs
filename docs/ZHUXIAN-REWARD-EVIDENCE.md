# 主线副本收益证据识别

整理：**Codex**，2026-11-26。

## 背景

历史真机日志显示，主线副本可以进入 BOSS 面板、完成重置和扫荡、看到「扫荡战报」并返回主城，但 OCR 未在原 `REPORT_SUM_REGION = [950,760,1850,900]` 识别到「总计获得」，因此结果正确记为待确认，而不是误报成功。

本次先离线检查 `_shot/` 与历史归档中的全部截图，并使用 Windows `zh-Hans-CN` OCR 搜索「扫荡战报」「总计获得」。结果没有找到真实战报截图；找到的 `z1`～`z9`、`s_r*` 和 `shot_zfail*` 实际为登录、选服、副本地图、回详情或 0 次面板。因此不能凭空移动 ROI，也不能把「看到战报」放宽为收益成功。

## 本次保守增强

位置：[`src/tasks/zhuxian.js`](../src/tasks/zhuxian.js)。

在 `_waitReport()` 已经确认「扫荡战报」标题后，才执行 `_confirmReward()`：

1. 先查历史窄区域 `[950,760,1850,900]`，保持原判据。
2. 再查更宽的汇总区域 `[650,650,2150,1050]`，兼容版本缩放或位置轻微变化。
3. 最后才查战报正文 `[500,550,2300,1150]`。
4. 只接受明确关键词：`总计获得`、`累计获得`、`共获得`。无关文字如「战报奖励」仍为待确认。
5. 三个区域的 OCR 原文会进入诊断日志，失败时通过 `sgs.debugShots.save(..., "zhuxian_total_unconfirmed")` 保存一张专用调试图。

调试图仍受现有截图规则限制：固定 `.nomedia` 目录、程序命名、普通文件、最近 20 张轮转；不写入相册，不删除用户文件。

## 结果语义

- 任一明确关键词命中：返回 `success`，说明战报标题和收益汇总均已确认。
- 只看到战报标题、未识别收益汇总：返回 `unconfirmed`，消息为「已见战报但收益汇总未确认」，并保存诊断证据。
- 没有等到战报：仍按原逻辑失败，不能宣称扫荡成功。
- 日常编排中 `allowReset:false` 不变，0 次直接跳过，不会花元宝重置。
- 独立副本入口仍沿用原有 `allowReset` 设置；本改动不改变消费授权。

## 验证

`tests/task-results.js` 增加到 30 项，新增覆盖：

- 三个收益关键词均可确认成功。
- 汇总文字位于宽区域或正文区域时可识别。
- 无关文字不能提升为成功。
- 待确认时只保存一张诊断帧，并在结果中保留未确认原因。
- 原有取消、重置、扫荡和返回主城安全测试继续通过。

全套 13 组回归、构建、bundle 语法和差异检查通过。由于当前没有授权重新执行副本扫荡，本次不主动消耗体力或元宝；真机只部署并执行只读玩家信息检查。下一次用户明确授权副本任务后，可根据新生成的 `zhuxian_total_unconfirmed` 截图精确校准真实 ROI，而不是继续猜测坐标。
