# 小乔入口与结果弹窗兼容修复

整理：**Codex**，2026-11-26。

## 真机现象

在第三个账号验证「邮件 → 小乔日常」：

1. 邮件增强后的 5 秒轮询成功识别奖励并返回主城。
2. 小乔主模板 `entry-left.png` 在左侧带的 OpenCV 匹配分数只有 0.6696，低于 0.75 阈值，因此旧逻辑在打开助手前失败，没有进入消费流程。
3. 离线分析显示旧窄条模板 `xiaoqiao_entry.png` 在同一左侧带匹配 0.9154，位置中心约 `(19,483)`，与历史入口位置一致。
4. 启用高分后备模板后，小乔可以正常打开面板、点击开启并识别完成。
5. 完成后又出现标题为「挑战竞技场」的结果弹窗；旧标题候选只包含「军团一键援助」等，导致模块虽识别绿色完成条，却未关闭这个弹窗。

## 入口修复

[`src/tasks/xiaoqiao.js`](../src/tasks/xiaoqiao.js) 增加：

- `ENTRY_FALLBACK = xiaoqiao/xiaoqiao_entry.png`
- `ENTRY_FALLBACK_TH = 0.9`

匹配顺序：

1. 原左侧主模板，阈值 0.75。
2. 原右侧头像模板，阈值 0.75。
3. 旧窄条后备模板在左侧带，阈值 0.9。
4. 旧窄条后备模板在右侧带，阈值 0.9。

后备模板仍只允许左右侧带，不做全屏匹配；低分候选不会触发点击。日志记录命中模板、阈值、区域和中心坐标。

## 结果弹窗修复

结果弹窗标题候选增加真机观察到的「挑战竞技场」，当前列表为：

- 军团一键援助
- 挑战竞技场
- 执行结果
- 日常结果

只有任务上下文为 `xiaoqiao`、标题位于限定结果区域且绿色完成条或明确结果状态存在时，才点击该弹窗自己的关闭 X。恢复器同样读取这个标题列表，其他任务上下文看到相同文字不会授权点击。

## 验证

- OpenCV 对新账号真机截图离线验证：主模板 0.6696，后备模板 0.9154。
- `tests/task-results.js` 增加到 37 项，覆盖高分后备入口、低分不点击、两个结果弹窗标题关闭、弹窗残留失败和取消保护。
- `tests/daily-recovery.js` 增加到 35 项，覆盖「军团一键援助」和「挑战竞技场」的任务上下文限制与安全关闭。
- 全套回归、构建和 bundle 语法检查通过。
- 真机验证确认后备模板可打开小乔并执行到完成；当前游戏弹窗由用户手动处理，代理不主动点击。

## 边界

此修复不放宽主模板阈值，也不把主城展示角色当作入口。后备模板必须在限定侧边区域达到 0.9 分才会点击。若后续账号仍无法识别，应先保存调试图并更新模板，而不是全屏搜索或降低阈值。
