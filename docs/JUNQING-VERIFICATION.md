# 紧急军情入口与奖励弹窗验证

整理：**Codex**，2026-11-26。

## 真机现象

用户确认主城存在紧急军情后，首次运行 `junqing` 被跳过，日志显示三轮均未识别到入口。离线 OpenCV 对真机截图匹配发现：

- 模板 `special_event/jinjijunqing.png` 实际中心约为 `(1257,1001)`，匹配分 `0.9838`。
- 旧入口区域 `[1000,930,1250,1090]` 只得到 `0.2734`，因为模板左边界已在旧 ROI 外。
- 多账号底部图标排列会整体居中移动，固定小区域不再可靠。

## 入口修复

`ENTRY_REGION` 扩展为下方中部安全区域 `[650,800,1800,1180]`，阈值仍保持 `0.8`，不做全屏匹配，也不降低阈值。

无入口跳过时会通过 `sgs.debugShots.save(..., "junqing_entry_missing")` 保存专用调试图，避免肉眼可见入口却静默跳过。

## 奖励弹窗误判

修复入口后第二次真机运行：

1. 成功识别并点击紧急军情入口。
2. 成功打开「敌军入侵，十万火急」面板。
3. 成功识别并点击「一键挑战」。
4. 真机画面出现「恭喜获得」奖励弹窗，奖励包含觉醒丹和神魂，底部出现多个「已击杀」。
5. 旧代码在奖励弹窗仍遮挡军情标题时立即检查 `_panelOpen()`，因标题不可见而抛出“面板未保持”，导致任务标红失败。

这不是挑战失败，而是检查顺序错误。奖励弹窗本来就可能短暂遮住下方军情面板标题。

## 结果检查修复

`run()` 现在保持以下顺序：

1. 点击一键挑战。
2. `_dismissReward()` 等待并关闭明确识别到的「恭喜获得」弹窗；未出现则记录可能无奖励，不盲点。
3. 弹窗处理后再取新帧检查军情面板是否仍在。
4. 检查三个「已击杀」区域；0 个为失败，1～2 个为待确认，3 个为成功。
5. 关闭军情面板并严格复检主城。

新增测试复现“奖励弹窗临时遮住面板标题，关闭后显示已击杀”的场景，防止再次把成功挑战误判为失败。

## 当前状态与下次验证

本次真机已实际消耗一次军情挑战并出现奖励和已击杀，但由于旧代码提前抛错，奖励弹窗需要用户手动关闭。修复版已构建并通过：

- `tests/task-results.js`：38 项，包含奖励遮挡场景。
- `tests/regression.js`：10 项，包含扩大入口区域和无入口诊断截图。
- 构建、bundle 语法和差异检查通过。

下次出现紧急军情入口时，再用修复版跑一次完整自动链路，预期成功关闭奖励弹窗、识别 3/3 已击杀、关闭军情面板并通过主城复检。若仍异常，保留调试图和状态记录，不重复挑战。
